El pipe |> es, junto con %>%, la forma más elegante de escribir código en R. Desde R 4.1 (2021) traes el pipe nativo incorporado: no necesitas instalar nada.

¿Qué es un pipe?

Un pipe encadena el resultado de una expresión como primer argumento de la siguiente. En lugar de escribir código “de adentro hacia afuera”:

sum(round(sqrt(abs(x)), 2))

Escribes de izquierda a derecha, que es como razonamos:

x |> abs() |> sqrt() |> round(2) |> sum()

El ejemplo que lo cambia todo

Imagina que quieres el promedio de ventas por ciudad, sólo de las ciudades con más de 5 pedidos, ordenado de mayor a menor. Sin pipe:

head(arrange(summarise(group_by(filter(datos, pedidos > 5), ciudad), media = mean(ventas))), 3)

Horroroso. Con |> se lee solo:

library(dplyr)

Attaching package: 'dplyr'
The following objects are masked from 'package:stats':

    filter, lag
The following objects are masked from 'package:base':

    intersect, setdiff, setequal, union
set.seed(42)

datos <- data.frame(
  ciudad = sample(c("Madrid", "Bogotá", "Lima", "CDMX"), 200, replace = TRUE),
  ventas = round(rnorm(200, 500, 120)),
  pedidos = sample(1:10, 200, replace = TRUE)
)

datos |>
  filter(pedidos > 5) |>
  group_by(ciudad) |>
  summarise(media = mean(ventas)) |>
  arrange(desc(media))
# A tibble: 4 × 2
  ciudad media
  <chr>  <dbl>
1 CDMX    542.
2 Bogotá  508.
3 Madrid  506.
4 Lima    457.

Lee el código en voz alta: “toma datos, filtra, agrupa, resume y ordena”. Eso es exactamente lo que hace.

|> nativo vs %>% de magrittr

Característica |> (nativo) %>% (magrittr)
¿Requiere librería? No, viene en R Sí, magrittr/dplyr
Pasar a un argumento distinto No directo Sí, con .
Velocidad Muy rápido Rápido
Mensajes de error Más claros A veces confusos

¿Y si necesito pasar a otro argumento?

Con |> puedes usar el placeholder _ (R 4.2+):

df |> summarise(n = n(), .by = grupo)      # .by va al final
1:10 |> lm(y ~ x, data = mtcars, _)         # ejemplo conceptual

En la práctica, la mayoría del código encadena en el primer argumento, así que |> cubre el 95% de los casos.

Tip pro: método _ globalmente

En cuanto dominas el pipe, nunca más quieres escribir sin él. Todos los paquetes del tidyverse (dplyr, tidyr, ggplot2, stringr…) están diseñados para funcionar como eslabones de una cadena.

library(ggplot2)

datos |>
  group_by(ciudad) |>
  summarise(media = mean(ventas)) |>
  ggplot(aes(x = reorder(ciudad, media), y = media)) +
  geom_col(fill = "#146C94") +
  coord_flip() +
  labs(title = "Ventas medias por ciudad", x = NULL, y = "Media") +
  theme_minimal(base_size = 13)

💡 Regla sencilla: si tu operación es un paso más en el procesamiento de datos, llévala por el pipe. Lee tu código como una frase y todo encajará.

Resumen

  • |> viene incluido en R 4.1+. No instalas nada.
  • Escribe horizontalmente (de izquierda a derecha), no anidado.
  • Combínalo con dplyr y ggplot2 para análisis limpios y legibles.

Domina el pipe y tu código (y tu cabeza) te lo agradecerán. 🚀
